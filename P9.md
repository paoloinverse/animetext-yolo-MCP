## What landed

**9.1** — `model_store.manifest_entry_for()` + `verify_file()` (states `match` / `mismatch` /
`unrecorded` / `absent`), and `DetectionEngine._open_failed()` on the failure path: intact weights
blame the runtime, corrupt ones name the file, both hashes and the two `fetch_models.py` commands.
Online, a mismatch retries once via `_retry_via_hub()` and says so in `status().detail` plus
`engine.recovered_via_hub`; offline retries never happen (asserted by a socket tripwire). The
corrupt file is never moved or deleted. New: `override_files` on the bundled opener, so a replaced
path survives for the session on every thread. 12 tests in `tests/test_model_store.py`.

**9.2** — `EngineStatus.model_list_is_fallback` (so `to_dict`, `--model-status`, the badge and the
MCP door read one field), `EngineModel.detail` + `...model_list_is_fallback` on the wire, the fifth
badge (`models_badge_text`, `ControlPanel.set_model_list_status`) and a "Refresh models" toolbar
action on a worker thread with a signal back.

*Found on the way (fixed in the same pass):* `DetectionEngine.model_list_is_fallback` was a
property that **calls `refresh_models()`** — so wiring it into `status()` as first written would
have given every status call a 10-second network budget. `status()` now reads `_names_offline`
passively and the property keeps the "ask again" meaning; a test asserts `status()` never lists.
Its docstring had also been claiming the MCP reported the flag since P7 — it never had (that was
the gap this subpart closed).

**9.3** — `Pipeline.reocr_blocks()` (+ `_file` / `_bytes`), job kind `reocr` (`start_reocr*`,
single-flight like a page), the 21st tool `reocr_blocks` (reuses `RunPipelineResult`, so the
output shape is the one every result already has), and a right-click **Re-read this block** on the
block table. `RESULT_STAGES` gained `"reocr"` — schema enum, `from_dict`, and `ocr_ran` (which now
says True for a re-read: it has text, only some of it re-read). `block_id_list()` is the shared id
check, so a door with no document can still answer "is that a list?", and the MCP door validates
ids against the document before starting a job rather than failing three seconds later.
The paperwork trail moved together, as it had to: catalog regenerated, `docs/MCP.md` row and the
20→21 prose, README (three places), `docs/ERROR-MATRIX.md` per-tool row, five `WIRE_CASES` rows,
`SIGNOFF["tools"] = 21` with the reason, `SPEC_TOOLS | POST_SPEC_TOOLS` in `test_mcp_server.py`.
33 new tests (12 pipeline, 6 door, 5 GUI, 10 store/base/mcp). Suite: **1146 passed**, 1 skipped.

*Found on the way:* the result JSON schema pins `stage` to an enum, so a new stage is a schema
change, not just a Python constant — the validator test caught it.

**9.4** — `core/warmup.py`: `warm_devices(devices, config, …)` builds a **cold engine pair per
device** (D85), warms it — load, then one throwaway 64×64 detection and a 96×32 crop read — and
releases it, returning `WarmupOutcome(requested_device, device, warm, load_ms, probe_ms, detail)`
with `total_ms` on top (D87). `--warm-devices cpu,cuda` (or `all`) prints the table with the
"asked → got" column and exits; `--verbose` adds the JSON. `--preload-off` is now honoured in both
GUI and headless paths, and the GUI's warm-up records `load_ms`/`probe_ms`/`total_ms` instead of a
wall-clock sum. A device that cannot load is a row, not a crash — that is the answer someone
sweeping for a working device came for. `warm_devices(None)` sweeps cpu+cuda while `[]` is an
error (D86). The sweep is local-only (D83, unchanged). ~20 tests in `tests/test_p8_lifecycle.py::TestDeviceSweep`.

**9.5** — `core/doctor.py` + `--doctor`: 15 read-only checks over the machine (Python floor and the
imgutils ceiling, `dghs-imgutils`, `onnxruntime` **checked without importing imgutils**, numpy
against the pin read from imgutils' own metadata, torch and CUDA, `transformers`, the two doors,
the bundle's three halves, the manifest cross-check, disk, the token's *source*, a CJK face, the
MCP bind). Prose by default, JSON on `--verbose`, and the exit code is the one a real run would
have hit (D89): `0` usable, `8` for a missing extra, `12` for a bundle that is not there offline.
Under `--mock` the engine checks say `skip` and why, because the fakes need none of them. The
doctor imports no backend and never imports `imgutils` (D88); the manifest is cross-checked by
size, never hashed (D90); a token appears as source + length, never as a fingerprint (D91).
`docs/UPSTREAM.md` carries both `dghs-imgutils` issues drafted, paste-ready, each with the
file:line, a proposed fix and a one-line repro, plus what we do meanwhile. 68 tests in
`tests/test_p9_doctor.py`, including the socket tripwire, the no-write check, a subprocess that
makes `import imgutils` raise, and a test that fails when upstream *fixes* either quirk.

*Found on the way (fixed in the same pass):* asking metadata for `PySide6` says "the window is not
installed" on a machine that has it — the wheel is published as `PySide6_Essentials` — so
`Context.version()` now takes the names to try in order. And the README's Python-3.14 row blamed
`ImportError: cannot import name 'Str' from 'ast'`: `yolo.py` does `import ast`, so the real
failure is an `AttributeError` on `ast.Str` while a model's label metadata is being parsed. The row
and `docs/UPSTREAM.md` now say the same true thing, and `--doctor` reports it before a page is
loaded rather than after.

## Decisions taken while planning (each is revisable, none is silent)

| # | Decision | Why |
|---|---|---|
| D80 | **9.1 verifies on the failure path only, never on load.** A mismatch is reported as `ENGINE_LOAD_FAILED` with `expected`/`got`/`path`/`steps`; the online retry happens once, after the diagnosis, and is recorded in `status().detail` | hashing 77–226 MB on every load would tax the common case to serve a rare one; and the diagnosis is the valuable half — the retry is a convenience on top of it |
| D81 | **9.3 produces a whole new document, not a patch.** Same image, same detections, same ids/colours/reading order; new `created_at`, `timing_ms`, and the re-read blocks' `text`/`flags` | `result://latest` and `save_result` promise "one document describes one page". A patch would make the latest result unreadable on its own, and every consumer would have to know how to splice. The cost is one re-serialized document |
| D82 | **9.3's tool is `reocr_blocks`, and it takes `block_ids` + the same overrides `run_pipeline` takes** | symmetry with `get_result(block_ids=…)`: the ids you read are the ids you re-read. Overrides stay config-shaped, so nothing new needs a grammar |
| D83 | **9.4 keeps `warmup_report` off the MCP surface; `--preload-off` and `devices:` exist, the table stays local** | a per-device latency table is machine-specific noise in a document-shaped API, and nothing on the other side of the wire can act on it. The proof an agent needs is still `engines[].warm` |
| D84 | **9.5's `--doctor` is read-only and offline-safe: it never installs, never downloads, never writes** | its whole job is to describe the machine before something else changes it. The moment it fixes something it stops being a doctor |
| D85 | **9.4's sweep is a CLI action that owns its engine pairs, not a `devices=` option on the app's warm-up job** (a deliberate deviation from proposal 4's wording). `warm_devices()` builds a cold pair per device, warms it, releases it; `--warm-devices` prints and exits; `start_warmup()` keeps its single-device meaning | doing it on the job would mean one process swapping the pair the window, the MCP door and any running job share — a device change dressed up as a measurement. A benchmark that can disturb the thing it measures is worth less than the number it prints |
| D86 | **9.4: `warm_devices(None)` sweeps cpu + cuda; `warm_devices([])` is an error** | "you didn't say" and "say the usual ones" are different answers, and the second must never be inferred from the first — otherwise a caller passing an empty list gets a machine-wide sweep it never asked for |
| D87 | **9.4: `WarmupOutcome` carries `requested_device` next to `device`, and `total_ms` next to `load_ms`/`probe_ms`** | the whole point of a per-device table is the pair "asked cuda, got cpu"; one device column cannot say it. `total_ms` is the number a benchmark reads, and deriving it in six places is how it drifts |
| D88 | **9.5: the doctor reads installed metadata and the filesystem; it imports no backend and never imports `imgutils` at all.** Versions come from `importlib.metadata`, presence from `find_spec`, CUDA from `nvidia-smi` on `PATH`, and the real answer about a GPU stays with `--warm-devices` | importing `imgutils` *is* the hazard being diagnosed (D11: it pip-installs at import). A doctor that changes the machine it is describing has stopped being a doctor, and one that hangs on a broken CUDA driver cannot report on it |
| D89 | **9.5: the doctor's exit code is the code a real run would have produced** — 0 when nothing blocks, otherwise the first blocking finding's `EXIT_CODES` entry; `--mock` downgrades the engine checks to `skip` | a report that always exits 0 cannot gate CI, and one that prints "not usable" and then exits 0 contradicts itself. The codes already mean this: 8 is "missing extra, broken weights, no provider", 12 is "not here offline" |
| D90 | **9.5: the manifest is cross-checked by *size*, never by sha256** | `fetch_models.py --verify` owns the hash sweep (33 files, ~3 s here and tens of seconds on a slow disk); the doctor's answer has to arrive in milliseconds. A size mismatch catches the realistic corruption — the truncated copy — for free. D80 hashes on the *load-failure* path; this is the *diagnostic* path, and the two rules point at each other |
| D91 | **9.5: the doctor reports a token's source and length, never a fingerprint** | `check_hf_access.py` masks first-6/last-4 because it is a live check you run yourself; a doctor report is the thing you paste into a bug report, and no question a partial value answers is worth the leak risk |
| D92 | **9.5: the two upstream issues are drafted, not filed** (`docs/UPSTREAM.md`) | filing needs this repository to have a GitHub identity, which it has no business inventing. What was owed was the text with the file:line, a repro and a proposed fix, kept where the README rows can point at it — and a test that goes red when upstream changes, so the drafts cannot quietly rot |
| D95 | **The repository publishes only what the project may publish: no `animetext_studio/models/`, no `sample_scans/`, no machine paths, nothing over 100 MB.** A clone rebuilds the bundle with `scripts/fetch_models.py`. This amends D26 — the bundle stays part of a *copy*, which is what D26 was actually about, and is never part of a *repository* | three reasons, deliberately not merged into one rule: the AnimeText weights are their author's to distribute and re-publishing them is bad manners regardless of what the GPL permits; the Hayai snapshot is 604 MB and four files pass GitHub's hard limit, so the push is rejected rather than warned about; and the scans are the user's, which nothing here licenses. Pinned by `TestWhatTheRepositoryPublishes`, which reads `git ls-files` — the published set, not the folder. (D93 and D94 are in tracking.md Turn 20, where the two sign-off defects were found.) |

## Carried forward, unchanged (the "do not" list from P8)

* The app **reports, it does not decide** (D58/D60). No language policy, no sub-crop splitting, no
  de-duplication — not here, not as a flag.
* Offline means **no socket**. `paths.offline` is never overridden, including by 9.1's retry.
* Byte-determinism of the result document for the same page and parameters.
* Generated files (`docs/QA.md`, `docs/ERROR-MATRIX.md`, `schemas/mcp-tools.json`) are regenerated
  by their scripts, never hand-edited.
* No secret in the tree, no URL in a default test, no network in the default suite.

## What landed — 9.6, the trail (2026-11-26)

The five enhancements were finished; this subpart made the **paperwork** say so, and running the
doors for real turned up two defects that only a sign-off run can find.

**The catalog.** `schemas/mcp-tools.json` is current — 21 tools, `detail` and
`model_list_is_fallback` in the `get_status`/`list_models` output schemas, `reocr_blocks` among
the tools — and a fresh dump is byte-identical to the committed file. Verifying that is what
exposed **D94**: `--dump-mcp-tools PATH` passed the path *positionally* into
`write_catalog(service, path)`, so it ignored PATH and rewrote the catalog that ships in the
wheel. The test that "wrote a copy to tmp_path" had the same bug, so it regenerated the shipped
file and compared it with itself — a check that repairs its own subject. `path=` is honoured
now, and both tests assert the shipped file is untouched.

**The matrix.** 84 → **91** faults, each with a case the sweeps run, not just a row: the four
re-OCR refusals at the service door (empty id list, unknown id, no page `NO_IMAGE`, page with no
document `INVALID_ARGUMENT` — the asymmetry against `get_result` is D81, now written down where
someone will read it), the corrupt bundled file at the offline door, and the two empty-option
refusals at the CLI. `docs/ERROR-MATRIX.md` regenerated; its prose gained a paragraph on the one
door deliberately *not* in the table — `--doctor`, which never refuses because it is not running
the thing it examines (D89).

**D93, found by running the doors.** `--warm-devices ""` opened the **GUI**. `main()` dispatched
its string-valued actions on truthiness, so an empty value was indistinguishable from an absent
flag: `--warm-devices ""` and `--export-config ""` fell through to the default action and started
a window, `--validate-config ""` did the same, `--dump-mcp-tools ""` too, and `--out ""` wrote
nothing and exited 0. D86 had promised an empty device list is *refused* — the core kept that
promise, the door never delivered it. Now the four options that decide an action or a destination
refuse an empty value (`INVALID_ARGUMENT`, exit 2, `details.option` names the flag); `--config ""`
is still "no config file", deliberately, and pinned as the exception.

**The QA table.** 115 → **131** requirements: a `P9` group of sixteen rows covering the five
enhancements and the two sign-off defects, every row citing a node id that exists. `FOLLOW_UPS`
rewritten — the four items P9 shipped are off the open list, block colours and the language
policy stay, and two honest ones were added: the two upstream issues are **drafted, not filed**
(D92), and `scripts/bench_models.py` (ADDENDUM item E) still isn't built, though `--warm-devices`
is now the primitive it would use. `docs/QA.md` regenerated; its verification table gained the
`--doctor` and `--warm-devices` rows.

**README.** The fifth badge (`models: presets — <why>`) is documented next to the other four;
right-click → **Re-read this block** is the "what to do" for `⚠` and **Refresh models** is in the
Controls list; `stage` is `"detect" | "full" | "reocr"` in the result-document comment (it said
two values while the schema allowed three); a Troubleshooting row separates a bundled file that
is *absent* from one that is *present and corrupt*; the counts (91 faults, 131 requirements,
1253 tests, D1–D94) are the measured ones.

**docs/MCP.md** documents `engines[].detail` and `engines[].model_list_is_fallback` — the 9.2
wire fields whose row had never been written. **docs/UPSTREAM.md** pointed at
`TestTheUpstreamClaimsAreStillTrue`, a class that has never existed; it now names
`TestTheUpstreamDrafts::test_the_quoted_source_is_still_the_installed_source`, which is the test
that goes red when upstream moves.

**Measured, this run.** 1253 passed / 41 deselected offline (~41 s) · `-m models` 40 passed /
1 skipped offline (~50 s) · `fetch_models.py --verify` 33 files hash-clean, "usable offline" ·
both generators `--check` clean · `--gui-smoke --mock` ok · `--doctor` 15 checks, 14 ok / 1 warn
